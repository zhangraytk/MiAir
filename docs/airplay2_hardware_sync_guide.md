# MiAir AirPlay 2 真实硬件多设备同步测量与校准指南

本指南用于指导在无硬件修改、不刷机、不 Root 的前提下，通过外部声学测量手段，对多台小米小爱音箱在 AirPlay 2 原生多选同步播放时的物理发声时间差进行高精度测量、归因分析与参数校准。

---

## 1. 核心概念与时序偏差分类

在 AirPlay 2 体系中，发送端与接收端（Shairport Sync + NQPTP）之间使用 PTP (IEEE 1588) 纳秒级时钟保持精确对齐。然而，下游路径为：
```
Shairport Sync (PTP 同步) -> FIFO -> MiAir HTTP 服务 -> Wi-Fi -> 小爱音箱网络缓冲区 -> 闭源解码器 -> DAC 扬声器
```
因此，**PTP 纳秒同步并不等同于最终扬声器发声同步**。必须严格区分以下 4 类物理发声偏差：

| 偏差类型 | 产生根因 | 表现特征 | 消除/优化手段 |
| :--- | :--- | :--- | :--- |
| **1. 初始固定时间偏移**<br>*(Initial Fixed Offset)* | 不同型号小爱音箱固件的网络拉流策略、解码器前置缓冲（Pre-roll Buffer）大小不同。例如 Play 增强版预加载约 800ms，Sound Pro 预加载约 400ms。 | 每次开始播放时，一台音箱恒定比另一台滞后固定的几十到几百毫秒。 | **可完全消除**：通过 Web UI 配置每台音箱的 `airplay2_latency_offset_ms` 进行毫秒级初始时差补偿。 |
| **2. 长期累积时钟漂移**<br>*(Cumulative Clock Drift)* | 小爱音箱硬件本地晶振频率与发送端参考时钟存在几个到几十个 ppm (parts-per-million) 的物理偏差。 | 连续播放数十分钟后，两台音箱的相位差逐渐缓慢拉开（例如每 10 分钟漂移 20~50 ms）。 | 硬件限制。由于小爱固件未提供 DAC 实时消费游标回传，服务器无法闭环调整 DAC 采样率；暂停后恢复可重新对齐。 |
| **3. 缓冲突变与丢包**<br>*(Buffer Jumps / Drops)* | 局域网 Wi-Fi 偶发丢包、空口信道拥塞或重传延迟，导致小爱本地网络缓冲区排空（Underflow）。 | 播放过程中突然出现一次卡顿、杂音，随后时差发生跳变。 | 提升 Wi-Fi 5GHz 覆盖质量；配置适当的 `airplay2_prebuffer_ms`（建议 100~300ms）。 |
| **4. 相对于原生设备偏差**<br>*(Offset vs Native HomePod)* | 原生 AirPlay 2 音箱（HomePod / Apple TV）具有端到端硬件 DAC 严密时钟锁相控制。 | 小爱音箱整体比原生 HomePod 滞后 100~400ms。 | 测量出小爱音箱相对于 HomePod 的平均滞后值，在 MiAir 全局或单机设置负向偏移提前输出。 |

## 2. 测量环境与物料准备

### 2.1 硬件设备
1. **待测音箱**：2 台或多台小米小爱音箱（放置在同一房间，相距 1~2 米）。
2. **测试音源设备**：iPhone、iPad 或 Mac（iOS >= 15 或 macOS >= 12）。
3. **声学测量设备**：
   - 带有**双声道（立体声）输入**的电脑（或外置双通道 USB 声卡，如 Focusrite Scarlett / 任何 3.5mm 立体声 Line-in）。
   - 2 支麦克风（或领夹麦克风），分别放置在音箱 A 与音箱 B 的出声孔前 5~10 厘米处。
   - 麦克风分别接入声卡的 **左声道 (CH1)** 与 **右声道 (CH2)**。
   - *（简易替代方案）*：两部智能手机靠近各自音箱使用录音机同时录音，通过波形特征对齐（精度略低）。

### 2.2 测试音频制作
必须使用具有明确时间戳特征的**周期性短脉冲音频**（Click Track / Pulse Track），不要使用普通音乐进行测量。

脉冲音频规范：
- **采样率**：44,100 Hz，16-bit 立体声。
- **波形**：每隔 1.000 秒发出一段持续 10 毫秒的 1 kHz 正弦脉冲（脉冲起始点严格对齐秒边界），其余 990 毫秒为绝对静音。

#### Python 生成脚本 (`make_sync_track.py`)
```python
import wave, struct, math

SAMPLE_RATE = 44100
DURATION_SEC = 120  # 2 分钟测试音频
PULSE_DURATION_MS = 10
PULSE_FREQ = 1000

with wave.open("sync_pulse_track.wav", "w") as wav:
    wav.setnchannels(2)
    wav.setsampwidth(2)
    wav.setframerate(SAMPLE_RATE)
    
    pulse_samples = int(SAMPLE_RATE * (PULSE_DURATION_MS / 1000.0))
    total_frames = SAMPLE_RATE * DURATION_SEC
    
    frames = bytearray()
    for f in range(total_frames):
        pos_in_sec = f % SAMPLE_RATE
        if pos_in_sec < pulse_samples:
            # 产生 1kHz 纯音脉冲并施加简易汉宁窗防爆音
            window = 0.5 * (1 - math.cos(2 * math.pi * pos_in_sec / pulse_samples))
            val = int(30000 * window * math.sin(2 * math.pi * PULSE_FREQ * (pos_in_sec / SAMPLE_RATE)))
        else:
            val = 0
        frames.extend(struct.pack("<hh", val, val))
        
    wav.writeframes(frames)
print("sync_pulse_track.wav 生成完毕")
```

## 3. 测量与校准实施步骤

### 步骤 1：软件录音就绪
1. 在电脑上打开音频工作站软件（推荐免费开源的 **Audacity** 或 **Reaper**）。
2. 新建一个立体声轨道，输入设备选择连接麦克风的双声道声卡。
3. 麦克风 L 紧贴音箱 A，麦克风 R 紧贴音箱 B。
4. 确保两支麦克风到各自音箱喇叭的物理距离一致（空气中声速约为 340 m/s，1 厘米距离差对应约 0.029 ms，影响极小，保持 5cm 左右即可）。

### 步骤 2：发起 AirPlay 2 原生多选播放
1. 在 iPhone / Mac 上播放 `sync_pulse_track.wav`。
2. 打开“控制中心” -> 点击 AirPlay 图标。
3. 在设备列表中，**同时勾选**音箱 A 与音箱 B。
4. 此时两台音箱将开始播放嘀嗒脉冲声。

### 步骤 3：波形录制与时间差提取
1. 在 Audacity 中点击“录制”，录制 30~60 秒的波形后停止。
2. 放大波形至毫秒级别（将时间标尺单位切换为 `hh:mm:ss + milliseconds`）。
3. 观察左声道（音箱 A）与右声道（音箱 B）的脉冲尖峰：
   - 记录第 5 个脉冲的左声道脉冲尖峰时间：$T_{A}$
   - 记录第 5 个脉冲的右声道脉冲尖峰时间：$T_{B}$
   - **发声时间差**：$\Delta T = T_{B} - T_{A}$
   - 若 $\Delta T > 0$，说明音箱 B 滞后于音箱 A；若 $\Delta T < 0$，说明音箱 B 提前于音箱 A。

### 步骤 4：在 Web UI 中调整延迟补偿
1. 访问 MiAir Web 控制台（默认 `http://<服务器IP>:8300`）。
2. 在左侧设备列表中找到需要调整的音箱：
   - **重要认知：时差与预缓冲的物理意义**：
     - **时差 (ms)**：调整 Shairport Sync 在 PTP 时间轴上的输出调度时间。
       - **负值（提前输出）**：如 `-3500 ms`，Shairport Sync 提前 3.5 秒将 PCM 输出到管道，MiAir 立即向小爱推流，刚好抵消小爱的云端下发延迟 + 网络缓冲 + 解码器前置缓冲，使物理扬声器发声时间与 HomePod 完美重合。
       - **正值（延后输出）**：如 `+500 ms`，推迟发声。
       - 量程已扩展至 **-15000 ms 至 +5000 ms**，完全覆盖小爱 Play 增强版等大缓冲机型。
     - **预缓冲 (ms)**：下游 HTTP 流服务器主动积压音频后再推送给小爱。
       - **警告**：预缓冲会**直接增加下游发声延迟**！若小爱滞后于 HomePod，**强烈建议预缓冲保持为 0 ms**，切勿误设为 1000ms（否则会导致发声进一步滞后 1 秒）。仅在网络极差频繁卡顿断流时适量开启。
   - **与原生 HomePod 混播对齐建议**：
     小爱音箱（如 Play 增强版 L05C）由于包含小米云端下发 + HTTP 连接建立 + 内部 256KB~512KB 环形播放缓冲区，通常整体滞后 HomePod 约 **2.0 秒 至 4.5 秒**。
     建议直接将该音箱的时差设置为 `-3000 ms`（若仍慢则进一步调至 `-3500 ~ -4500 ms`），并将预缓冲设为 `0 ms`。
3. 点击“保存设置”，随后在设备卡片中点击“重启 AP2”。
4. 重新播放并录音，再次测量 $\Delta T$。理想情况下小爱音箱与 HomePod 的脉冲尖峰将重合或相差在 $\pm 10\text{ ms}$ 以内。

### 步骤 5：原生 HomePod 混播加入特性
- **加入顺序兼容性**：
  - **小爱后加入**：HomePod 播放中，在 iOS 勾选小爱音箱，小爱无缝加入同步播放。
  - **HomePod 后加入**：小爱播放中，在 iOS 勾选 HomePod 时，iOS 会短暂重协商群组时间线。MiAir 具备 2.5 秒平滑防抖宽限期并持续推送保活静音，小爱连接保持完好且不向小米云端发停止指令，两台设备随后平滑进入同步混播。

## 4. 长期累积漂移测量法

为评估小爱音箱硬件晶振引起的长期漂移：

1. 保持多选播放持续运行 30 分钟。
2. 分别在播放的第 **1 分钟**、**10 分钟**、**20 分钟**、**30 分钟** 抓取录音样本。
3. 记录不同时间节点的脉冲时间差：
   - 第 1 分钟：$\Delta T_1$
   - 第 10 分钟：$\Delta T_{10}$
   - 第 20 分钟：$\Delta T_{20}$
   - 第 30 分钟：$\Delta T_{30}$
4. 计算漂移率：
   $$\text{Drift Rate} = \frac{\Delta T_{30} - \Delta T_{1}}{29\text{ 分钟}} \quad (\text{ms/min})$$
5. **观测结论记录**：
   - 如果漂移率小于 $1\text{ ms/min}$，在常规一两小时的家庭听歌场景中，时差变化在人耳可接受的临界门槛内（< 30ms），听感无明显双音或回声。
   - 如果发生偶然的大突变（例如某一分钟跳变 500ms），表明局域网网络出现抖动导致小爱触发了内部重新缓冲。可通过在 Web UI 调大 `预缓冲(ms)`（如从 0 调至 200ms）来提供缓冲安全裕度。

## 5. 工程验收标准与听感指导

- **$\Delta T < 10\text{ ms}$（高保真同步）**：
  同一房间双音箱听感宛如单一声源，立体声结像清晰，无相位抵消。
- **$10\text{ ms} \le \Delta T \le 20\text{ ms}$（良好多房间同步）**：
  人耳在同房间能感知轻微的空间混响/膨胀感，但绝无明显分立的回音（Echo）；若位于不同房间，体验极佳。
- **$\Delta T > 50\text{ ms}$（明显回音/不可接受）**：
  同房间内能清晰听出两次重音，必须按照本指南进行延迟参数补偿。
